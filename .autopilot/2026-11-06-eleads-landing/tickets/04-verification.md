## Что должно заработать

Сайт проверен так, как его увидит клиент и как его оценит Google: на трёх ширинах экрана, в
Lighthouse на мобильном, с выключенным движением и только с клавиатуры. Всё найденное, что
исправляется точечно, исправлено; остальное записано в отчёт с причиной. В `README.md` — как
запустить, собрать, куда положить материалы клиента и как задеплоить `dist/` на обычный хостинг.

## Критерии приёмки

- [ ] `docs/qa-report.md`: для 360 / 768 / 1440 — есть ли горизонтальный скролл (значение `scrollWidth`), что не так в раскладке; найденное исправлено или записано с причиной
- [ ] Lighthouse mobile по `npm run build && npm run preview` прогнан (`npx lighthouse` с headless Chrome); Performance, Accessibility, Best Practices, SEO записаны в отчёт; при Performance < 85 — исправлено, что исправимо, остальное с причиной. Если Chrome недоступен — сказано прямо, и прогон не выдуман
- [ ] Reduced motion: при эмуляции `prefers-reduced-motion: reduce` нет прелоадера, ревилов, параллакса, бегущей строки, анимации карты; весь контент виден — записано в отчёт
- [ ] Клавиатура: Tab проходит шапку, меню, hero, калькулятор, кейсы с модалкой, лайтбокс, слайдер, FAQ, подвал; фокус всегда видим; нет ловушек фокуса, кроме модалок; Esc закрывает всё открытое — записано в отчёт
- [ ] Поиск по `src/`: ни одной анимации `filter`, `blur`, `box-shadow`, `width`, `height`, `top`, `left`; `backdrop-filter` встречается один раз — в шапке; один `<canvas>` на странице
- [ ] `README.md`: установка, `dev`, `build`, `check`, куда положить видео/фото/логотипы/скриншоты (имена файлов из брифа), где править тексты и коэффициенты калькулятора, как выкладывать `dist/` на хостинг
- [ ] В отчёте раздел «Что не дотянуто» — честный список, включая все заглушки из «Открытых мест»
- [ ] `npm run check` зелёный
