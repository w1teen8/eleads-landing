# eLeads — лендинг Володимира Кучера (Telegram Ads)

Односторінковий сайт: Vite + vanilla JS, GSAP, Lenis. Весь текст лежит в JSON. Две языковые версии: украинская (по умолчанию, вшита в HTML при сборке) и английская (черновик, подставляется в браузере).

## Установка и запуск

Нужен Node 20+ (проверено на Node 24, npm 11).

| Команда | Что делает |
|---|---|
| `npm install` | поставить зависимости |
| `npm run dev` | локальный сервер с горячей перезагрузкой |
| `npm run build` | собрать статику в `dist/` |
| `npm run preview` | посмотреть собранный `dist/` локально |
| `npm run check` | тесты (`node --test`) и сборка — должна быть зелёной перед каждой выкладкой |

Один файл тестов: `node --test tests/<файл>.test.js`.
Проверка без анимаций: открыть сайт с `?nomotion=1` (то же, что `prefers-reduced-motion`).

Результат проверки скорости, экранов и клавиатуры — в `docs/qa-report.md`.

## Куда положить материалы клиента

Всё, что клиент присылает, кладётся в `public/` — Vite копирует это в `dist/` как есть.

| Что | Куда | Файлы |
|---|---|---|
| Видео первого экрана | `public/video/` | `hero-1080.mp4` (десктоп), `hero-720.mp4` (мобильный), `poster.jpg` (кадр-заставка). Пока файлов нет, показывается градиент. |
| Фото Володимира | `public/img/photo/` | PNG без фона. |
| Логотипы клиентов | `public/img/logos/` | 7 файлов SVG/PNG. |
| Скриншоты рекламы | `public/img/ads/` | 3 файла: канал, медиа, бот. |
| Скриншоты кейсов | `public/img/cases/<id>.webp` | путь указывается в `src/data/cases.json`, поле `screenshot` |
| OG-картинка, favicon | `public/og.jpg` (1200x630), `public/favicon.svg` | сейчас заглушки |

Важно: пока **подключены только видео первого экрана и скриншоты кейсов**. Фото, логотипы и скриншоты реклам в разметке сейчас показаны силуэтом, названиями и макетами — после получения файлов нужна небольшая правка `index.html` (место помечено меткой-заглушкой на самом сайте).

## Где править тексты и данные

Всё в `src/data/`:

| Файл | Что в нём |
|---|---|
| `content.ua.json` | украинские тексты всех секций (ключи вида `hero.title`) |
| `content.en.json` | английские тексты; набор ключей должен совпадать с украинским (проверяет тест). Пока черновик: `"draft": true` в корне — когда текст вычитан, строку убрать |
| `cases.json` | 7 кейсов: ниша, название, бюджет, результат, CPA, отзыв, список «что сделано»; значения «уточнити» / «TBD» — заглушки |
| `faq.json` | вопросы и ответы (по языкам) |
| `calculator.json` | коэффициенты калькулятора прогноза |
| `config.json` | ссылка и ник Telegram, ID аналитики (`ga4Id`, `metaPixelId` — пустые, пока не заданы, аналитика не подключается) |
| `geo-dots.json` | сетка точек карты мира и регионы |

В `index.html` нет текстов — только разметка с атрибутами `data-i18n="раздел.ключ"`. Новый текст = новый ключ в **обоих** `content.*.json`. Отсутствующий ключ роняет `npm run build` с перечнем.

### Коэффициенты калькулятора

Калькулятор считает по формулам из `src/sections/calculator-model.js`:
показы = бюджет / CPM x 1000; клики = показы x CTR; подписчики или пользователи бота = клики x конверсия; CPC и CPA — из них. Диапазон — медиана ± `spread` (0.15).

Числа — в `src/data/calculator.json`: `cpm` (по географии), `ctr` (по нишам), `cr` (конверсия: `subscribers`, `bot_users`), `budget` (границы и шаг ползунка).
Клиент заполняет форму **`client-data/calculator-template.csv`** (ниша; гео; цель; CPM в евро; CTR %; конверсия %; комментарий) — по ней значения переносятся в `calculator.json`. Пока файл не заполнен, там демо-значения и `"demo": true` — на сайте это показано дисклеймером; при замене на настоящие числа поставить `"demo": false`.

## Как выложить на хостинг

1. `npm install` и `npm run check` (должно быть зелёным).
2. `npm run build` — готовый сайт в папке `dist/`.
3. Загрузить **содержимое** `dist/` (не саму папку) в корень сайта на обычном хостинге: по FTP / SFTP или через файловый менеджер панели хостинга. Серверной части нет, PHP и Node не нужны.
4. Проверить в браузере: главная открывается, переключатель UA/EN работает, видео (если уже загружено) играет.

Замечания:
- Сайт рассчитан на раздачу из корня домена (пути вида `/assets/...`). Для подпапки нужен `base` в `vite.config.js`.
- В `dist/` попадает `robots.txt` (разрешить всё). Свой положить в `public/robots.txt` — тогда используется он; адрес `Sitemap:` добавить, когда будет известен домен.
- Если на хостинге включено сжатие gzip/brotli и кэш для `/assets/` — скорость будет выше, чем на `npm run preview`.
- OG-картинка подключена относительным путём `/og.jpg`; для превью в соцсетях добавить абсолютный `og:url` и адрес картинки, когда будет известен домен.

## Структура

```
index.html            разметка всех 14 секций (без текстов)
build/                плагин сборки: вшивает украинский текст и пишет robots.txt
src/main.js           точка входа: язык, секции, анимации, аналитика
src/core/             язык, DOM-помощники, форматы чисел, анимации (GSAP/Lenis), аналитика
src/sections/         по модулю на секцию (подхватываются по data-section)
src/styles/           tokens.css, base.css, layout.css, sections/*.css
src/data/             все тексты и числа (JSON)
public/               материалы клиента
tests/                node --test
docs/qa-report.md     отчёт о проверке и список «что не дотянуто»
```

Правила проекта: анимируются только `transform` и `opacity`; `backdrop-filter` — только в шапке; на странице один `<canvas>` (карта); без JS и при «уменьшить движение» весь контент виден.
