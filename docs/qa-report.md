# Отчёт о проверке (QA)

Дата: 2026-11-06. Сборка: `npm run build`, раздача: `npm run preview` (localhost:4173), браузер — Google Chrome (headless, управлялся через puppeteer-core; Lighthouse 13 через временный пакет, в `package.json` ничего не добавлено).
Скриншоты и скрипты проверки лежат вне репозитория и не коммитятся.

## 1. Горизонтальный скролл: 360 / 768 / 1440

| Ширина | `documentElement.scrollWidth` | `body.scrollWidth` | Горизонтальный скролл |
|---|---|---|---|
| 360 | 360 | 360 | нет |
| 768 | 768 | 768 | нет |
| 1440 | 1440 | 1440 | нет |

Элементы шире окна есть (градиент и свечение первого экрана, бегущая строка, трек слайдера отзывов), но все они в контейнерах с `overflow: hidden/auto` — это задумано. Проверка «текст шире своей коробки» (scrollWidth > clientWidth) нашла один реальный дефект:
- **#cta, 1440**: слово «ОБГОВОРИМО» (11vw) было шире колонки и заезжало на карточку с фото. Исправлено: в двухколоночной раскладке размер заголовка `clamp(3.25rem, 1rem + 6.4vw, 9rem)` (`src/styles/sections/cta.css`).

## 2. Lighthouse mobile (`npm run build && npm run preview`)

Прогонов много, потому что на этой машине результат «плавает» на ±5–8 пунктов (особенно TBT).

| | Performance | Accessibility | Best Practices | SEO |
|---|---|---|---|---|
| До правок (1-й прогон; 8 прогонов в диапазоне 78–85) | 79 | 97 | 96 | 91 |
| После правок (5 прогонов) | 96 / 90 / 92 / 96 / 86 (медиана 92) | 100 | 100 | 100 |

Метрики после: FCP 1.0–1.3 с, LCP 1.0–1.3 с (было 3.3 с), TBT 190–510 мс (было 290–500), CLS 0.006–0.008, Speed Index 3.3–3.5 с.
Один из пяти прогонов (86) — на пороге; запас небольшой, главный остаток — TBT от раскладки (layout) при троттлинге CPU x4. На настоящем хостинге со сжатием (gzip/brotli) обычно легче, чем `vite preview`.

Что исправлено ради этих чисел:
- **Google Fonts блокировали отрисовку** (оценка 490–826 мс): подключение переведено на `media="print" onload="this.media='all'"` + `<noscript>` (`index.html`).
- **LCP-элемент (подзаголовок первого экрана) прятался за заставкой** до конца прелоадера: теперь он виден сразу под шторкой и выезжает только `transform`-ом; остальной первый экран появляется как раньше. Тайминги появления первого экрана сокращены на ~0.35 с, прелоадер 1.2 → 1.0 с минимум (в рамках «1–1.5 с» из спецификации) (`hero.css`, `hero.js`, `preloader.js`).
- **Длинная задача при загрузке**: `initSections()` теперь отдаёт поток браузеру между секциями (`scheduler.yield` / `setTimeout`) (`src/main.js`).
- **Доступность 97 → 100**: подписи шагов процесса имели контраст 3.5:1 (`opacity .4`), теперь `.62`; у кнопок UA/EN `aria-label` не содержал видимого текста — теперь «UA · Українська» / «EN · English» (оба `content.*.json`).
- **Best Practices 96 → 100**: в консоли была ошибка (см. п. 6, карта).
- **SEO 91 → 100**: без `robots.txt` хостинг отдаёт `index.html`, и Lighthouse читал его как 1000+ ошибок robots. Плагин сборки теперь кладёт в `dist/` `robots.txt` (`User-agent: *`, `Allow: /`), если своего в `public/` нет (`build/i18n-prerender.js`, тест в `tests/prerender.test.js`). Строки `Sitemap:` нет — домен клиента неизвестен.

Что пробовал и не оставил: `content-visibility: auto` на нижних секциях — выигрыша не дало (в пределах шума) и рискует сбить расчёты ScrollTrigger.

## 3. prefers-reduced-motion: reduce (эмуляция, 360 px)

- `<html>` без классов `js-anim` / `motion-ok` / `lenis` / `js-preload`; прелоадер `display: none`, `hidden`.
- Ни одного секционного элемента с `opacity: 0` в раскладке, кроме задуманных: видео без файла (виден градиент), скрытые радио пилюль калькулятора, hover-иконки.
- Бегущая строка: `transform` не меняется за 1 с (стоит).
- Карта: канвас один, статичный кадр, цикл отрисовки не запускается; параллакса и ревилов нет (GSAP не грузится).
- `scrollWidth` 360.

## 5. Поиск по `src/` (ограничения на анимации)

- `transition` / `@keyframes` / `will-change` / GSAP: нет `filter`, `blur`, `box-shadow`, `width`, `height`, `top`, `left` (все `@keyframes` — только `transform`/`opacity`).

## 6. Проверка, которую ранние таски не могли сделать

**Пин #process (1440).** Секция закрепляется на `top: 0`, шаги загораются 1 → 7 по скроллу, после пина уходит без скачка: расстояние между низом секции и верхом #geo во всех замерах равно 0 (ни нахлёста, ни провала). Найдено и исправлено:
- Секция была выше окна (990 px при окне 900; на ноутбуке 768 — ещё больше), и пока длился пин, **низ (карточка-примечание) был обрезан**. Отступы теперь считаются от высоты окна (`process.css`); проверено 1440x900, 1440x768, 1280x720 — высота секции равна высоте окна. Если секция всё же не помещается, пина нет, работает вариант как на мобильном (`process.js`).
- Пин создавался один раз при загрузке: после resize 1440 → 700 пин оставался (`pin-spacer` висел), а 700 → 1440 не создавался. Теперь `gsap.matchMedia()` пересоздаёт его на пороге 900 px: 1440 → 1100 → 700 пересчитывает высоту и снимает пин, 700 → 1440 создаёт.

**GEO-карта.**
- Рисуется (около 31 тыс. непрозрачных пикселей), один `<canvas>`.
- Анимация идёт в экране и **стоит вне экрана** (кадры идентичны).
- Найден и исправлен **реальный баг**: у регионов с отрицательной долготой (Америка) фаза пульса была отрицательной, `ctx.arc` падал с `IndexSizeError`, и секция «geo» переставала запускаться (консоль: `[boot] секция «geo» не запустилась`). Математика вынесена в `src/sections/geo-model.js`, тест `tests/geo-model.test.js`.
- Hover по пункту списка и клик меняют карточку региона (Європа, затем United Kingdom).
- На 360 px карточка перекрывала карту и список — теперь на экранах < 900 px она встаёт под картой (`geo.css`).
- Не проверено: настоящий тач-тап по точке на карте (эмуляция тача не гонялась); на мобильном карта маленькая (294x110), основной способ выбора региона — список.

**Переключение UA → EN.** Кнопка EN в подвале: `<html lang="en">`, `<title>` английский; в тексте страницы 0 сырых ключей (`a.b.c`) и 0 кириллических узлов; на проходе по всем 14 секциям ни один видимый заголовок/абзац/пункт не остался с `opacity < .5`. Ошибок в консоли нет.

Метрики после: FCP / LCP 1.0–1.3 с, TBT 250–450 мс, CLS 0.006–0.008, Speed Index 3.4–3.5 с.
Первая версия кэша суши (рисунок + PNG-кодирование слоя сразу при загрузке) давала медиану 83 (TBT 600+ мс) — слой теперь готовится, только когда карта в 600 px от экрана.

**Что проверено в браузере:**
- Меню 640×360 (Lenis остановлен `lockScroll`): колесо — `scrollTop` 0 → 705 (максимум), тач-драг — 0 → 705; `.menu__cta` в окне (низ 328 из 360), страница под меню не сдвинулась. Без `data-lenis-prevent` тот же тач-драг: 0 → 0.
- Процесс: по скроллу меняется только `transform` слоя `.process__fill` (1440: `scaleX` 0 → 0.34 → 0.68 → 1; 390: `scaleY` 0 → 0.53 → 1), инлайн-стилей у `.process__draw` нет; шаги загораются как раньше.
- Свечения ниш и материалов: за курсором меняется только `transform` слоя, `background-image` постоянен.
- GEO: на canvas в DOM за кадр 21 `arc` (7 регионов × точка и 2 кольца), суша — CSS-фон из слоя вне DOM, перерисовывается при смене размера; `<canvas>` в DOM — один.
- Прелоадер сломан (узел процентов удалён до init — `tick` и `finish` бросают): в 3.0 с у всех узлов первого экрана `opacity` 1 и нет сдвига, шторки нет. Обычная загрузка: заставка как раньше.
- Цифры: UA → EN, три круга вкладок — каждое значение равно строке из `content.en.json` («4,500», не «4 500»); смена языка посреди докрутки — тоже.
- Ловушка фокуса (одна, `trapFocus` в `core/dom.js`): модалка кейса и лайтбокс — Tab и Shift+Tab не выходят; меню 360 — по кругу пункты и бургер; после Esc ловушки нет.

Причина падения пре-рендер-теста: cwd `c:\…` против резолвинга модулей `C:/…` — ключи html-proxy у Vite расходились; `vite.config.js` теперь задаёт `root` от своего файла с заглавной буквой диска.
