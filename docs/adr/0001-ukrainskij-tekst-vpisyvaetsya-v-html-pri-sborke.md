# 0001. Украинский текст вписывается в HTML при сборке

## Контекст

Клиент требует, чтобы весь текст жил в JSON и правился без вёрстки, а страница при этом индексировалась и читалась без JS. Язык по умолчанию — украинский, английский — черновой перевод.

## Решение

Все 14 секций лежат в `index.html` статически, без единой фразы в исходнике. При `dev` и `build` Vite-плагин подставляет украинский текст из `content.ua.json` в узлы с `data-i18n`. Английский подставляется в рантайме, без перезагрузки. Повторяющиеся списки (ниши, кейсы, FAQ, услуги) рисуются в JS по `<template>`. Отсутствующий ключ валит `build` со списком ключей, а в `dev` даёт предупреждение.

## Почему

- Рисовать всю страницу из JSON в браузере: без JS остаётся пустой экран, поиск и превью в мессенджерах ничего не видят, LCP хуже. Не подошло из-за требования «контент виден без JS» и цели Lighthouse 85+ на среднем Android.
- Писать украинский текст прямо в `index.html` и держать JSON только для английского: клиент правил бы два места, а правило «текст только из JSON» нарушилось бы.
- Рантайм-подстановка украинского тоже: тот же пустой экран до запуска скрипта.
- Для списков пре-рендер не берём: клиент должен добавлять карточку правкой JSON, а не вёрстки.

## Последствия

- Любая правка текста требует пересборки, а не только замены файла на хостинге.
- Опечатка в ключе ломает сборку целиком. Это сознательно строже, чем «молча показать ключ»: пустой текст не должен доехать до клиента. Ключ в рантайме при этом выводится как есть.
- Списки без JS не видны: у калькулятора и кейсов без скрипта остаются только заголовки и ссылки.
- Два механизма подстановки (сборка для UA, рантайм для EN) надо держать согласованными. Для этого тест сверяет наборы ключей в двух файлах.
